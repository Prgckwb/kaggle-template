# 変更を細かい粒度でコミット & プッシュする

変更を論理的な単位にグルーピングし、gitmoji + 日本語のコミットメッセージで1つずつコミットする。
最後にまとめて push する。

## Git 規則

- **コミット**: gitmoji + 日本語。1コミット = 1つの論理的な変更
- **push**: 作業の区切りごと、実験完了時
- amend ではなく**新しいコミットを作成**する
- `--no-verify` や `--force` は使わない

## gitmoji 一覧

| gitmoji | 用途 | 例 |
|---------|------|-----|
| 🧪 | 実験の追加・変更 | `🧪 exp001_baseline を追加` |
| 🐛 | バグ修正 | `🐛 データローダーの index エラーを修正` |
| ✨ | 新機能 | `✨ OOF 分析機能を追加` |
| ♻️ | リファクタリング | `♻️ サイドバーを折りたたみ対応に改修` |
| 📝 | ドキュメント更新 | `📝 CLAUDE.md に実験規則を追記` |
| 🎨 | コード・UI の見た目改善 | `🎨 Knowledge ページのカードデザインを改善` |
| 🔧 | 設定ファイルの変更 | `🔧 config.yaml に run_name を追加` |
| 🗑️ | 不要なファイルの削除 | `🗑️ 旧 Discussions ページを削除` |
| ⬆️ | 依存関係のアップグレード | `⬆️ PyTorch を 2.x に更新` |
| 🚀 | デプロイ・パフォーマンス改善 | `🚀 Data ページの遅延読み込みを実装` |
| 🔀 | ブランチのマージ | `🔀 feature/xxx を main にマージ` |
| 🏷️ | 型・アノテーションの変更 | `🏷️ experiments サービスに型ヒントを追加` |

## フェーズ 1: 変更の把握

1. `git status` で未コミットの変更（untracked, modified, deleted, staged）を一覧取得
2. `git diff` と `git diff --cached` で差分の内容を把握
3. **変更がない場合**: 「コミットする変更がありません」と伝えて終了

**危険なファイルの検出**:
- `.env`、`credentials.json`、`*.pem`、`*.key` 等のシークレットファイルが含まれている場合は **警告** し、コミット対象から除外する
- `src/*/output/` 配下のファイルが含まれている場合は **警告**（gitignore されているべき）

## フェーズ 2: 論理グループへの分類

変更を論理的な単位にグルーピングし、コミット案を作成する。

**分類の基準**:
- **同じ機能・目的に関する変更**をまとめる
  - 例: 実験追加 → config + train.py + model.py + README
  - 例: ダッシュボード改修 → template + router + service
- **異なる目的の変更は分ける**
  - 例: バグ修正とリファクタリングは別コミット
  - 例: ドキュメント更新とコード変更は別コミット
- **削除は独立したコミット**にすることが多い
- $ARGUMENTS があればそこから意図を読み取り、分類に反映する

**各グループに以下を決定する**:
1. 対象ファイルのリスト
2. gitmoji の選択
3. 日本語のコミットメッセージ（簡潔に、何を・なぜ変更したか）

## フェーズ 3: ユーザー確認

分類結果を以下の形式で提示する:

```
コミット 1: 🧪 exp001_baseline を追加
  - src/exp001_baseline/train.py (new)
  - src/exp001_baseline/config/config.yaml (new)
  - src/exp001_baseline/README.md (new)

コミット 2: 📝 Experiments テーブルを更新
  - README.md (modified)

コミット 3: ...
```

ユーザーが以下を調整できる:
- グループの統合・分割
- コミットメッセージの修正
- コミット順序の変更
- 特定ファイルの除外

**承認を得てから**次のフェーズに進む。

## フェーズ 4: コミット実行

承認されたグループごとに順番に実行:

1. `git add {files}` — 対象ファイルをステージ
2. `git commit -m "{gitmoji} {message}"` — コミット作成
3. 次のグループへ

全コミット完了後:
- `git push` を実行（リモートブランチがあれば `-u` 付き）

## フェーズ 5: 完了報告

- 作成したコミットの一覧を表示（短いハッシュ + メッセージ）
- push 先のブランチ名とリモート URL を表示
- push が失敗した場合は原因を説明し、対処法を案内
