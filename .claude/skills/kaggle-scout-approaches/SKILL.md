# アプローチスカウト: 探索チェックリストの生成と多様性スコアリング

このスキルはコンペの種類に基づいて網羅的なアプローチチェックリストを生成し、
どのカテゴリが探索済みか/未探索かを可視化する。
「何を試していないか」を構造的に把握し、探索空間の偏りを防ぐ。

## フェーズ 1: コンペの理解

1. **コンペ情報の収集**
   - `docs/competition-profile.yaml` を Read して `competition.type`（supervised / optimization / simulation）と `metric` を把握（SSOT）
   - `docs/official/overview.md` を Read してタスクの詳細・評価指標の詳細を把握
   - `docs/official/data.md` を Read してデータの形式・規模を把握
   - データ種別の観点でコンペの種類を判定する:
     - テーブルデータ（分類 / 回帰）
     - 画像（分類 / 検出 / セグメンテーション）
     - NLP（分類 / 生成 / QA / 情報抽出）
     - 音声 / 信号（分類 / 検出 / 生成）
     - 時系列（予測 / 異常検知）
     - マルチモーダル
     - その他（最適化、シミュレーション等）

## フェーズ 2: チェックリストの生成

コンペの種類に応じて、以下のカテゴリ構造でチェックリストを生成する。
各カテゴリには具体的な手法例を含める。

### テーブルデータ（分類/回帰）の場合

```
## モデリング
- [ ] 勾配ブースティング
  - LightGBM / XGBoost / CatBoost
  - ハイパーパラメータ最適化（Optuna）
- [ ] ニューラルネット
  - TabNet / FT-Transformer / NODE
  - MLP + Entity Embedding
- [ ] 線形モデル
  - Ridge / Lasso / ElasticNet / SVR
- [ ] 距離ベース
  - KNN / SVM

## 特徴量エンジニアリング
- [ ] 基本的な統計量（mean, std, min, max, skew, kurtosis）
- [ ] 交互作用特徴量
- [ ] ターゲットエンコーディング
- [ ] 頻度エンコーディング
- [ ] 時系列特徴量（該当する場合）
- [ ] テキスト特徴量（TF-IDF, embeddings）
- [ ] 次元削減（PCA, UMAP, t-SNE as features）

## バリデーション戦略
- [ ] StratifiedKFold
- [ ] GroupKFold
- [ ] TimeSeriesSplit（該当する場合）
- [ ] Adversarial Validation

## アンサンブル
- [ ] 単純平均 / 加重平均
- [ ] スタッキング（2段階以上）
- [ ] ブレンディング

## 後処理
- [ ] 閾値最適化（分類の場合）
- [ ] ランク平均化
- [ ] 制約条件の適用
```

```
## モデルアーキテクチャ

- [ ] ハイブリッド（CoAtNet, EfficientFormer）

## 事前学習・転移学習

- [ ] ドメイン固有の事前学習

## データ拡張
- [ ] 基本拡張（Flip, Rotate, Crop, ColorJitter）
- [ ] 高度な拡張（Mixup, CutMix, Mosaic）

## 学習テクニック
- [ ] Progressive Resizing

- [ ] 半教師あり学習（Pseudo Labeling）
- [ ] 損失関数の工夫（Focal Loss, ArcFace 等）

- [ ] マルチモデルアンサンブル
- [ ] マルチスケールアンサンブル
- [ ] TTA アンサンブル
```

### NLP の場合

```
## モデル
- [ ] Encoder 系（BERT, RoBERTa, DeBERTa, ELECTRA）
- [ ] Decoder / LLM（GPT, Llama, Mistral fine-tuning）

## 推論最適化
```

### 音声/信号の場合

```
## 表現
- [ ] スペクトログラム（Mel, Log-Mel, PCEN）
- [ ] 波形直接処理
- [ ] 手作り特徴量（MFCC, Chroma, Spectral Contrast）

## モデル
- [ ] スペクトログラム + CNN/ViT（画像分類として扱う）
- [ ] 事前学習モデル（wav2vec2, HuBERT, BEATs, AST）
- [ ] 1D-CNN / WaveNet / SampleCNN
- [ ] 手作り特徴量 + 勾配ブースティング

## データ処理

- [ ] 外部データの活用
- [ ] セグメント分割戦略

## アンサンブル
```

上記はテンプレートであり、**コンペの固有事情に合わせてカテゴリを追加・削除・修正する**こと。例えばコンペ固有のドメイン知識に基づくアプローチや、Discussion で話題になっている手法を追加する。

## フェーズ 3: 既存実験との照合

1. **EXP_SUMMARY.md を Read** して全実験の一覧と結果を取得
2. **各実験の README.md を Read** して手法の詳細を確認
3. **チェックリストの各項目について**:
   - 対応する実験があれば `[x]` に変更し、実験名と CV/LB を付記
   - 部分的に探索済み（例: LightGBM は試したが XGBoost は未）の場合は `[~]` にして詳細を付記

## フェーズ 4: 多様性スコアの算出

**トップレベルカテゴリ単位**（`## モデリング` 等の見出し直下の `- [ ]` レベル。例: 「勾配ブースティング」「ニューラルネット」）で以下の計算を行う。配下の具体的手法（LightGBM / XGBoost 等）はカテゴリの探索状態の判定材料であり、分子・分母には数えない:

```
カテゴリの探索状態:
  [x]（配下に完了した実験が1つ以上ある）     → 1.0
  [~]（配下の一部の手法のみ試した）          → 0.5
  [ ]（未着手）                              → 0.0

探索済みカテゴリ数 = 全トップレベルカテゴリの探索状態の合計
全カテゴリ数       = トップレベルカテゴリの総数
探索多様性スコア   = (探索済みカテゴリ数 / 全カテゴリ数) * 100
```

分子と分母は必ず同じ粒度（トップレベルカテゴリ）で数えること。粒度が混ざるとスコアが 100% を超える等、無意味な値になる。

スコアに応じた評価:
- 0-25%: 「探索初期段階。多くの有望なアプローチが未試行です。」
- 26-50%: 「中程度の探索。まだ試していないカテゴリに大きな伸びしろがあります。」
- 51-75%: 「広範な探索。残りのカテゴリやアンサンブルに注力する段階です。」
- 76-100%: 「高い探索率。各カテゴリの深掘りや組み合わせの最適化を検討してください。」

## フェーズ 5: 推奨の提示

チェックリストと多様性スコアをユーザーに提示し、以下を強調する:

1. **最も有望な未探索カテゴリ**（コンペの特性と既存の結果を踏まえて 1-3 個を推奨）
   - 各推奨について、なぜこのコンペで有望と考えるかの根拠を示す
2. **既存の best アプローチとの補完性**
   - アンサンブルした場合に多様性が高まるかどうか
3. **探索の優先順位**
   - 高: 未探索かつ有望なカテゴリ
   - 中: 部分的に探索済みで深掘りの余地があるカテゴリ
   - 低: コンペの特性上あまり有効でないと考えられるカテゴリ

## フェーズ 6: チェックリストの保存

`docs/approach_checklist.md` にチェックリストを保存/更新する。

ファイル形式:

```markdown
# Approach Checklist

> コンペの種類: {タイプ}
> 最終更新: {YYYY-MM-DD}
> 探索多様性スコア: {X}% ({評価})

## チェックリスト

{フェーズ 3 で照合済みのチェックリスト}

## 推奨アプローチ（優先順位順）

1. **{カテゴリ名}** — {推奨理由}
2. **{カテゴリ名}** — {推奨理由}
3. **{カテゴリ名}** — {推奨理由}
```

ファイルが既に存在する場合は内容を更新する。存在しない場合は新規作成する。

## フェーズ 7: 次のアクション

ユーザーに次のアクションを確認する:
- 推奨カテゴリから実験を開始する場合は `kaggle:new-experiment` を案内
- さらに戦略的な分析が必要な場合は `kaggle:review-strategy` を案内
